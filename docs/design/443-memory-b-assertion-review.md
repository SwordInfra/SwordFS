# Memory B-class assertion reconciliation (#443)

**Contract gate:** #439 records 179 original Memory cases: 109 B, 69 C, one A.
The 69 C-class dispositions are in #442, which is not rewritten here.
This inventory preserves all original asserted expressions alongside the explicit
Redis assertion statements in the corresponding test. The expected property
(success/error/output/post-state) can be checked directly without relying on
test-name similarity. Source/test references are relative to the repository root.
The 109 B cases are assessed against real Redis semantics, not a fake Memory backend.
When several redis tests together establish an observable contract, the precise
supplementary witness is cited below; Memory-private transaction plumbing,
pointer caching and exact internal key layouts are not portable obligations.

**Disposition:** 101 primary Redis witnesses plus 8 multi-test/reworked
dispositions identified below. B005, B030 and B067 received stronger Redis
contract assertions in #443, and B017/B100/B112/B167 have independent tests
for edges not shown in the original primary B mapping. B004 intentionally
retires Memory-only shared-pointer/cache identity while retaining typed
capability success/error coverage. All rows cite original and Redis test code.
The CI gate remains required to prove the new witnesses run successfully.

## Assertion-level review of composite scenarios

- **B004:** the Memory store returned a cached object with exact pointer equality. That is its private caching strategy. Generic contract: opening a supported COW capability returns a nonnull typed object, wrong type and null-output/bridge are rejected. Redis metadata and the typed COW tests cover those externally meaningful properties.
- **B005:** the previous mapping exercised initial success and failed update, not successful retry and cleanup. #443 extends the same Redis test: the next retry must advance public head and private snapshot together and emit a cleanup candidate for the old revision.
- **B017:** `RedisMetaOpsTest.GetInodesReturnsAlignedPresentAndMissingResults` asserts three ordered slots including a hole and null output. The primary RedisMetaImpl test asserts present/missing at the engine surface.
- **B030:** the original rename-overwrite case checked direct inode survival, pending reclaim publication and completion after overwrite. #443 adds `RenameOverwriteVictimCompletesReclaimLifecycle` to test these as one Redis end-to-end lifecycle.
- **B067:** the primary Redis test checks POSIX ACL inheritance, mode, persistent access ACL and failure; the new `PosixDefaultAclDistinguishesFilesDirectoriesAndSymlinks` exercises no-default-ACL umask, directory inherited default ACL, removing it without mode mutation, regular files never carrying default ACL, and symlink ACL refusals.
- **B100:** `UnlinkPublishesDurableOrphanCandidate` proves zero links, live inode/chunk and durable orphan on unlink; `PrepareReclaimFreezesRecordAndRemovesLiveMetadata` proves pending, removal and completion. This is a legitimate composite witness, not one-test parity.
- **B112:** `PendingDeleteBatchBoundsVisitsAndContinuesWhileQueueMutates` demonstrates bounded batch progress; `VisitorArgumentsAreValidated` verifies zero batch/null visitor/null output, and `PendingDeleteBatchVisitorAbortRetriesCurrentBufferedRecord` verifies abort.
- **B167:** Redis `SetAttrShrinkQueuesOnlyMaterializedSparseObjectsForCleanup` uses a high `ChunkIndex` of `(uint64_t{1} << 32) + 1000000000ULL`, retrieves that exact chunk and verifies cleanup does not alias small indices.
